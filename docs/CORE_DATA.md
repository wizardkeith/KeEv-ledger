# Phase 2A core data

Pure Dart `lib/core/` and `lib/features/local_profile/domain/` do not import Flutter or Drift. `Money` holds `Currency` plus signed integer minor units; HKD 123.45 is 12345, JPY 500 is 500. Supported range is **−9,223,372,036,854,775,807 to +9,223,372,036,854,775,807** minor units. The most negative SQLite int64 is excluded so negation stays representable. Addition/subtraction use `BigInt` intermediates and reject overflow and currency mismatch. No implicit exchange.

`Currency.fromCode` accepts uppercase HKD, USD, EUR, GBP, JPY, THB and CNY. JPY has zero decimals; the others currently have two. Unknown codes require an explicit registry/schema review. `ExactFxRate.majorRatio` stores positive, reduced `BigInt` numerator/denominator as **target major units per source major unit**. Conversion multiplies exactly including both currencies' minor precisions, then rounds **once** to target minor units with signed HALF-EVEN. Future backup/API serialization must encode large integers as decimal strings; no authoritative `double` is used.

`LocalId` is a validated lowercase UUID v4. Production `SecureUuidV4Generator` uses `Random.secure`, independent of row order and cloud identity. `Clock.nowUtc` isolates technical time; `SystemClock` is the production implementation, fixed clocks support tests. Business transaction dates are represented separately by Phase 2B1 `BusinessDate` (validated calendar day, `yyyy-MM-dd`).

`LedgerDatabase` in `lib/infrastructure/local/` uses [Drift](https://pub.dev/packages/drift) with [drift_flutter](https://pub.dev/packages/drift_flutter) to create `keev_ledger.sqlite` in the app documents directory when opened. **SQLite is unencrypted**; the OS app sandbox is the current protection. The Phase 1 Local Only shell does not yet open SQLite; Phase 2B1 application/repository operations open and persist records offline. Tests use temporary real SQLite files. Data-layer `DriftLocalProfileRepository` maps Drift rows to domain values and maps known SQLite errors to typed failures; unexpected programming errors remain visible. `DriftLocalUnitOfWork` rolls back on exceptions **and** returned `Failure` results.

Schema **v1** is retained as the immutable initial local-profile snapshot at `drift_schemas/ledger_database/drift_schema_v1.json`. The active schema is **v3**: v1→v2 creates account, category and income/expense tables without replacing profiles; v2→v3 adds a single atomic transfer table. Direct v1→v3 runs both steps. v1, v2 and v3 snapshots and the migration verifier are committed. Real on-disk v2→v3 migration preserves the existing profile, accounts, categories and entries; reopen succeeds. See [local bookkeeping](BOOKKEEPING.md) for current models and Quick Add.

Development commands (Flutter 3.47.5 / bundled Dart 3.13.4): `flutter pub get --enforce-lockfile`, `flutter gen-l10n`, `dart run build_runner build`, `dart format --output=none --set-exit-if-changed lib test tools/capture_shell_test.dart tools/capture_typography_test.dart`, `flutter analyze`, `flutter test`. Code generation writes `ledger_database.g.dart` to source control. Native Android/iOS compilation still requires SDK/Xcode. This foundation introduces no cloud, login or analytics service.
