# KeEv Ledger typography — KeEv Global Typography Standard v1.0

Phase 1A replaces the provisional Phase 1 system-font choice. The five official **unmodified variable TTFs** below are locally bundled via `pubspec.yaml`. Each font carries its upstream SIL Open Font License 1.1 in `assets/fonts/<upstream-directory>-OFL.txt`; the full notices accompany the delivered source. Upstream: [Google Fonts official repository](https://github.com/google/fonts/tree/main/ofl). All downloads were taken directly from `raw.githubusercontent.com/google/fonts/main/ofl/…` and file signatures, internal names, weight axes and coverage were inspected. There is no Google Fonts package, runtime network fetch or platform font as a primary family.

The files are renamed for simple asset paths; **font contents have not been modified**. One variable file per family covers the weights in its axis, without seven duplicate static files per CJK language. Plus Jakarta Sans has a maximum of 800, so the theme's normal 400–700 hierarchy stays inside its range. No italic variant is bundled because no UI element currently requires italic. Total uncompressed font data is approximately 39.7 MB, before mobile build processing; native APK/IPA size remains unverified. Licence files remain separate and readable in the source archive.

## Resolution and semantic hierarchy

`KeEvTypography.familyFor` in `lib/design_system/theme.dart` centralizes locale selection; `keevTheme` applies it to the complete Material text theme and widget defaults. `KeEvApp` updates its localized Theme when a user switches language. `zh-HK` and `zh-CN` select different **primary** families. The existing locale resolver maps Hant/HK to Hong Kong and Hans/CN to Simplified; the default unknown-locale policy stays unchanged. No screen makes an independent font decision.

The Material text theme supplies display, page title (`headline*`), section (`headlineSmall`), card title (`title*`), body (`body*`), secondary body/caption (`bodySmall`), label and button (`label*`) semantics, retaining Material's size/weight defaults. The design system adds bounded line-height tokens from 1.18 (display) through 1.4/1.42 (body) to leave room for CJK/Thai marks; components use these semantic styles. `KeEvTypography.financialAmount` applies `FontFeature.tabularFigures()` to medium/large amount styles; the font remains the locale's chosen sans family. Plus Jakarta Sans contains OpenType `tnum`. In the tested upstream binaries, Noto Sans HK/SC/JP/Thai digits have equal advance widths even without an explicit `tnum` feature, so the requested feature is harmless and digit columns remain regular-width. Future money formatting must be validated with actual monetary data in Phase 2.

Mixed-script fallback order is primary locale family, then **other bundled approved families** (including Plus Jakarta Sans and Thai), then PingFang/Hiragino/Thonburi OS fallback. `fontFamilyFallback` is for missing glyphs, so Latin characters already present in a CJK font can retain that locale's primary font for consistent line metrics; Latin-only `en` screens select Plus Jakarta Sans. Sample Latin, HK/SC characters, Japanese, Thai tone marks, yen, currency punctuation, obscured-card bullets and long figures are exercised in Phase 1A checks. No cross-locale family is selected as the **primary** family; fallback can render glyphs not present in that primary font. For unseen scripts/emoji the OS may still supply terminal fallback glyphs.

Consumer in-app reports will retain these Sans UI families. Formal PDF report fonts such as Tinos/Noto Serif are explicitly excluded from the normal app theme. Original logo lettering remains raster artwork.

## Verification scope

`test/widget/typography_test.dart` checks each primary theme mapping, independent HK/SC selection, font declarations/asset signatures, 200% mixed-script rendering in five locales × two themes, large amount wrapping and tabular-feature tokens. `docs/evidence/phase_1a/FONT_VALIDATION.json` records offline fontTools cmap and figure-width checks against all sample strings. Headless font rendering verifies Flutter/widget layout, not Android/iOS native font rasterization or real device screen-reader output. See `docs/ACCESSIBILITY.md` and `checkpoints/PHASE_1A.md` for outstanding platform checks.
